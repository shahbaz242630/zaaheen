Claude Code se souvient-il d’une session à l’autre ?

Oui, au sein d'un même projet sur un même ordinateur. Claude Code démarre chaque session avec un contexte vierge, puis charge deux types de notes : les fichiers CLAUDE.md que vous écrivez et l'auto memory qu'il écrit lui-même. Ni l'un ni l'autre ne vous suit dans le dossier de mémoire d'un autre projet, sur un autre ordinateur ou dans une autre application d'IA.

Par Zaaheen · Mis à jour le 22 octobre 2026

Ce dont Claude Code se souvient

La documentation d'Anthropic (How Claude remembers your project) décrit deux façons dont les connaissances passent d'une session à la suivante :

  • Les fichiers CLAUDE.md sont des instructions que vous écrivez : comment compiler le projet, les règles à suivre, ce qu'il faut éviter. Ils peuvent se trouver dans le projet, dans votre dossier utilisateur ou être définis par votre organisation, et tous ceux qui s'appliquent sont chargés au début de chaque session.
  • L'auto memory, ce sont des notes que Claude Code écrit pour lui-même pendant que vous travaillez : vos corrections, vos préférences et ce qu'il a appris sur le projet. Quand vous dites « retiens que les tests ont besoin d'une base de données locale », c'est là que ça va.

Ce sont dans les deux cas de simples fichiers texte que vous pouvez ouvrir et modifier. Dans une session, /memory les liste, les ouvre et active ou désactive l'auto memory.

Ce qui se charge au début de chaque session

L'auto memory vit dans un dossier propre à chaque projet, ~/.claude/projects/<project>/memory/, avec un fichier appelé MEMORY.md qui sert d'index. Seules les 200 premières lignes ou les 25 Ko premiers de cet index, selon la limite atteinte en premier, sont chargés au démarrage d'une session. Les notes détaillées se trouvent dans des fichiers thématiques séparés, que Claude Code ouvre quand il en a besoin.

Claude Code se souvient donc bien, mais l'essentiel de ce qu'il sait est consulté à la demande plutôt que lu à chaque fois. Garder l'index court, avec une ligne par souvenir, permet de garder l'important sous les yeux. Anthropic conseille de garder chaque CLAUDE.md sous les 200 lignes pour la même raison.

Ce qu'il ne transporte pas

La documentation est claire sur les limites :

  • Un dossier de mémoire par projet. Tous les worktrees d'un même dépôt le partagent, mais un autre dépôt a le sien, donc ce que Claude Code a appris sur vous dans un projet n'est pas dans le suivant.
  • Un seul ordinateur. L'auto memory est locale à la machine et n'est pas partagée entre machines ou environnements cloud.
  • Une seule application. Cursor, Codex, ChatGPT et Claude Desktop ne lisent pas le dossier de mémoire de Claude Code.

Pour les règles du projet, c'est exactement ce qu'il faut : elles appartiennent au projet. Pour les informations sur vous, comme la façon dont vous aimez les réponses, les outils que vous préférez ou ce sur quoi vous travaillez ce mois-ci, cela veut dire les répéter à chaque projet et à chaque application.

Se souvenir de vous d'un projet et d'une application à l'autre

Une mémoire qui vit en dehors de Claude Code comble ce manque. Claude Code peut se connecter à des outils grâce à MCP, la façon standard dont les applications d'IA se branchent sur des outils et des données. Il peut donc enregistrer des informations sur vous dans une mémoire que chaque projet, et vos autres applications d'IA, peuvent lire.

Zaaheen est une mémoire de ce type, pour Windows et Mac. Vous connectez Claude Code une seule fois, avec une commande depuis l'onglet Agents de Zaaheen, et elle est ensuite disponible dans tous vos projets Claude Code (pas à pas). Vos souvenirs restent chiffrés sur votre propre ordinateur.

Une bonne répartition : les règles du projet dans CLAUDE.md, ce que Claude Code apprend sur le projet dans l'auto memory, et ce qui est vrai à votre sujet dans une mémoire partagée que toutes les applications lisent.
