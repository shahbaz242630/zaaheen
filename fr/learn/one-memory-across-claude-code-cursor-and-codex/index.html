Comment garder une seule mémoire pour Claude Code, Cursor et Codex

Claude Code, Cursor et Codex ont chacun leur propre mémoire, et aucun ne lit celle des autres. Mettez les règles du projet dans un seul fichier AGENTS.md, que les trois savent lire, et gardez ce qui est vrai à votre sujet dans une mémoire partagée à laquelle les trois se connectent.

Par Zaaheen · Mis à jour le 22 octobre 2026

Ce que chacun conserve

D'après la documentation de chaque entreprise :

ApplicationSa propre mémoirePartagée avec les autres ?
Claude CodeLes fichiers CLAUDE.md que vous écrivez, plus l'auto memory qu'il écrit, dans un dossier par projet sur votre ordinateur (Anthropic)Non
CursorLes règles de projet dans .cursor/rules, les règles utilisateur pour tous vos projets, et AGENTS.md (Cursor)Non
CodexAGENTS.md, plus des souvenirs qu'il peut écrire dans ~/.codex/memories/, désactivés tant que vous ne les activez pas (OpenAI)Non, pas même avec ChatGPT

Une préférence que vous apprenez à Claude Code le lundi est donc nouvelle pour Cursor le mardi et pour Codex le mercredi. Les développeurs qui passent de l'un à l'autre finissent par répéter trois fois les mêmes choses, ou par tenir trois fichiers à jour à la main.

Règles du projet : un seul AGENTS.md pour les trois

Pour les règles qui concernent le projet lui-même, comme la façon de le compiler, de lancer les tests et les conventions à suivre, il existe désormais une réponse simple : AGENTS.md. Cursor le lit comme l'un de ses types de règles. OpenAI conseille d'y mettre les consignes que Codex doit toujours suivre. Et Claude Code le lit comme les instructions du projet quand le projet n'a pas de CLAUDE.md (à partir de la version 2.1.277).

Un seul fichier dans le dépôt, versionné avec le code, et les trois outils partent des mêmes règles. Si vous avez déjà un CLAUDE.md, la documentation d'Anthropic explique comment le faire pointer vers AGENTS.md pour que les deux ne se contredisent jamais.

Ce qu’ils savent de vous : une mémoire partagée

AGENTS.md n'est pas le bon endroit pour les informations sur vous. Elles ne font pas partie du projet, elles changent, et elles concernent tous les projets, pas un seul. C'est là qu'intervient une mémoire partagée : une mémoire en dehors des trois outils, à laquelle chacun se connecte grâce à MCP, la façon standard dont les applications d'IA se branchent sur des outils et des données.

Zaaheen est une mémoire de ce type, pour Windows et Mac, conservée chiffrée sur votre propre ordinateur. Chaque outil se connecte une seule fois : Claude Code avec une commande, Cursor avec un lien d'installation, et Codex avec quelques lignes dans son fichier de réglages (Claude Code, Cursor, Codex). Ensuite, ce que l'un d'eux enregistre sur vous, les autres peuvent le retrouver.

Notre test

Nous avons essayé avec Cursor, qui lisait une mémoire partagée contenant environ 15 informations sur une personne, enregistrées auparavant par une autre application. Les questions étaient du genre que l'on pose vraiment, et deux étaient conçues pour le piéger : l'une portait sur quelque chose que la mémoire ne contenait pas, l'autre était une question piège.

Les cinq réponses étaient justes, y compris les deux où la bonne réponse était « non ». Pour une mémoire, ce deuxième point compte autant que le premier : une application qui invente une réponse est pire qu'une application qui dit qu'elle ne sait pas.
